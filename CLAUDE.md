# Правила проекта (обязательны для всех этапов)

Репозиторий учебного задания из трёх частей: C++-библиотека `msgfmt`, Go-служба `ghreport` с Docker,
Python-интеграционные тесты. Спецификация: `docs/spec_part1.md`, `docs/spec_appendix_a.md`.

## 1. Ограничения ТЗ
- C++: только стандартная библиотека.
- Go: нет SDK GitHub и готовых Markdown-парсеров; только `net/http` и stdlib.
- Репозитории GitHub — только для чтения.
- Токены и секреты не попадают в код, образ, логи и историю git.

## 2. Контракт для каждой функции
Без исключений: публичные, внутренние, статические, методы, вспомогательные функции тестов
(кроме самих тест-кейсов). Контракт — комментарий перед функцией. Он описывает ПОВЕДЕНИЕ,
а не пересказывает имя функции.

- **C++ (Doxygen):** `@brief`; `@param <имя>` для КАЖДОГО параметра (тип, допустимые значения,
  владение/время жизни); `@return` (что, в каком формате, что значит «пусто»/`nullopt`) для не-void;
  `@pre`; `@post` (инварианты результата); `@throws` (что и когда, либо «не бросает»).
  Нарушение предусловия во внутренних функциях проверяется макросом `MSGFMT_EXPECTS` и бросает
  `ContractViolation` (даже в Release).
- **Go:** строки `Args:`, `Returns:`, `Errors:` в doc-комментарии (имя функции в первой строке).
- **Python:** docstring с секциями `Args:`, `Returns:`, `Raises:`.

Проверка: `python tools/check_contracts.py <каталог> [--tests <каталог тестов>] [--check-covers]`.

## 3. Тесты на всё
- Для каждой функции минимум один тест; на практике: нормальный случай, граничные значения,
  ошибочные входы, нарушение предусловия.
- Каждый тест помечается комментарием `// covers: имя_функции` (Python: `# covers: имя`; Go: `// covers: Имя`).
- Логика не прячется в анонимных namespace без доступа для тестов: помощники выносятся в namespace
  `detail` / внутренний пакет и тестируются напрямую.
- Тесты детерминированы, без `sleep`, без внешней сети.

## 4. Неоднозначности ТЗ
Правила приоритетнее примеров. Выбранное решение записывается в `docs/decisions.md`
(проблема → решение → почему → какой тест это фиксирует) и в README соответствующей части.

## 5. Git
- Небольшие атомарные коммиты в стиле Conventional Commits (`feat:`, `fix:`, `test:`, `docs:`,
  `build:`, `chore:`), на английском; коммит после каждого логического шага.
- Бинарники и каталоги сборки не коммитить.
- Не менять git config, не делать push, не переписывать историю (amend/rebase/force).

## 6. Язык
Документация — на русском; идентификаторы, комментарии контрактов и сообщения коммитов — на английском.
