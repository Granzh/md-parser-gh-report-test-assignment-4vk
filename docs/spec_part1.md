3. Часть 1. Библиотека разметки сообщений msgfmt (C++)3.1. Назначение
Клиенты мессенджеров передают форматирование отдельно от текста: сообщение представляется парой «чистый текст» и «список стилевых диапазонов», позиции которых измеряются в кодовых единицах UTF-16. Именно так устроены format ranges в Bot API корпоративных мессенджеров.

Библиотека msgfmt выполняет преобразование из разметки в такое представление: на вход подаётся строка в подмножестве Markdown, на выходе получаются чистый текст и отсортированный список диапазонов. Дополнительно библиотека умеет экранировать текст для повторной отправки.

3.2. Состав проекта и сборка
Каталог msgfmt/ содержит: include/ (заголовочные файлы), src/ (исходный код), tests/ (тесты), CMakeLists.txt, README.md.

Стандарт языка - C++17. Разрешена только стандартная библиотека; сторонние зависимости, в том числе готовые парсеры разметки, не используются.

CMakeLists.txt описывает исполняемую цель msgfmt и тесты, зарегистрированные в CTest.

Сборка и запуск тестов: cmake -S msgfmt -B build -DCMAKE_BUILD_TYPE=Release, cmake --build build, ctest --test-dir build.

Проект собирается без предупреждений с флагами -Wall -Wextra и корректно работает при сборке с -fsanitize=address,undefined: ни один запуск не должен приводить к сообщениям санитайзеров.

3.3. Входные данные и кодировки
Вход библиотеки и командной строки - последовательность байтов в кодировке UTF-8.

Некорректная последовательность UTF-8 - единственная предусмотренная ошибка (см. раздел 3.6).

Нормализация Unicode не выполняется: входные последовательности сохраняются в неизменном виде. Например, буква «й», записанная одной кодовой точкой и двумя, даёт разные байтовые строки и разные позиции диапазонов.

Переводы строк и управляющие символы не преобразуются и считаются обычными символами текста.

3.4. Термины
Чистый текст - результат разбора: входная строка без служебных маркеров разметки.

Кодовая единица UTF-16: символы основной плоскости (U+0000-U+FFFF) занимают одну единицу; символы вне основной плоскости - суррогатную пару, то есть две единицы.

Диапазон - четвёрка (style, offset, length, url). Поле style принимает значения bold, italic, code, link; offset - позиция первого символа в чистых единицах UTF-16; length - длина в тех же единицах; url - адрес ссылки, пустая строка для всех стилей, кроме link.

Служебные символы: *, _, обратная кавычка, [, ], (, ), \.

3.5. Правила разбора
Правила полностью определяют поведение библиотеки. При расхождении между правилами и примерами приоритет имеют правила.

1.  Разбор выполняется однопроходно, слева направо; на каждом шаге анализируется текущий открывающий маркер, диапазоны строятся по мере обработки.

2.  Открывающие маркеры: ** - стиль bold; _ - стиль italic; обратная кавычка - стиль code; [ - стиль link. Примеры: **a**, _b_, обратные кавычки вокруг c, [d](u).

3.  Открывающий _ распознаётся только на границе слова: перед ним начало текста или символ, не являющийся буквой или цифрой; после него - непробельный символ. Закрывающий _ распознаётся, если за ним следует конец текста или символ, не являющийся буквой или цифрой. Пример: строка a_b_c курсива не содержит.

4.  После остальных открывающих маркеров (**, обратная кавычка, [) должен следовать непробельный символ. Примеры: 2 ** 3 и ** 3 содержат литералы.

5.  Закрывающий маркер - ближайший подходящий, перед которым стоит непробельный символ.

6.  Если закрывающий маркер не найден или конструкция неполна, её символы выводятся в чистый текст как обычные (примеры 5, 12 и 15 приложения А).

7.  Содержимое стиля code выводится как есть: разметка внутри не интерпретируется, экранирование не действует.

8.  Ссылка имеет вид [текст](url): текст непустой и не содержит ]; url непустой, без пробельных символов и без ). Если условие нарушено, конструкция выводится как литералы. Пример: [текст]() - литералы.

9.  Экранирование: обратный слеш непосредственно перед служебным символом превращает этот символ в обычный; перед любым другим символом обратный слеш сохраняется как обычный символ. Пример: 2 \* 3 даёт текст 2 * 3.

10.  Вложенность разрешена для различных стилей: **жирный _и курсив_** даёт стиль bold на всём фрагменте и italic на слове «и». Маркер того же стиля внутри уже открытого стиля новый диапазон не открывает и выводится как текст.

11.  Пустой вход даёт пустой чистый текст и пустой список диапазонов.

12.  Диапазоны сортируются по offset по возрастанию; при равных offset - по length по убыванию; при полном совпадении интервалов первым идёт стиль, открытый раньше во входной строке. Частичные пересечения интервалов не возникают.

3.6. Формат вывода и командная строка
msgfmt без аргументов читает байты со стандартного ввода и выводит в стандартный вывод один JSON-объект UTF-8: {"text": <строка>, "ranges": [<диапазон>, ...]}; диапазон: {"style": <строка>, "offset": <целое>, "length": <целое>, "url": <строка>}. Коды возврата: 0 - успех; 2 - некорректный UTF-8, при этом выводится {"error": "invalid_utf8"}.

msgfmt escape читает байты со стандартного ввода и выводит текст, в котором каждый служебный символ предварён обратным слешем. Коды возврата те же, что у команды разбора; при некорректном UTF-8 выводится тот же объект {"error": "invalid_utf8"}.

Порядок полей JSON не фиксирован; лишние поля недопустимы. Вывод детерминирован и зависит только от входных байтов.

Пример вывода (форматирование переносов для наглядности):

{

  "text": "Привет, мир!",

  "ranges": [

    {"style": "bold", "offset": 8, "length": 3, "url": ""}

  ]

}


Пример работы команды escape для входа 2 * 3:

$ printf '2 * 3' | msgfmt escape

2 \* 3
