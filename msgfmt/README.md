# msgfmt

Библиотека и утилита разбора простой разметки сообщений (`**жирный**`, `_курсив_`, `` `код` ``,
`[текст](url)`, экранирование `\`). Результат — чистый текст и список диапазонов форматирования
с позициями в кодовых единицах UTF-16. Язык — C++17, только стандартная библиотека.
Спецификация: `docs/spec_part1.md`, `docs/spec_appendix_a.md`.

## Сборка и тесты

Команды из ТЗ:

```
cmake -S msgfmt -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build
```

Опции CMake:

- `-DMSGFMT_WERROR=ON` — предупреждения (`-Wall -Wextra`) считаются ошибками;
- `-DMSGFMT_SANITIZE=ON` — AddressSanitizer + UBSan (`-fno-sanitize-recover=all`: любое сообщение санитайзера
  завершает тест с ошибкой).

Режим с санитайзерами (проверен в Linux, g++ 14):

```
cmake -S msgfmt -B build-san -DCMAKE_BUILD_TYPE=Debug -DMSGFMT_SANITIZE=ON -DMSGFMT_WERROR=ON
cmake --build build-san
ctest --test-dir build-san
```

Полный набор проходит без сообщений санитайзеров и без предупреждений при `Debug` (-O0),
`RelWithDebInfo` (-O2) и `Release` (-O3), с санитайзерами и без них. На Windows (mingw) санитайзеров нет,
см. `docs/decisions.md`.

В `ctest` входят: модульные тесты каждого модуля, `test_parser_props` (перебор всех коротких строк),
`test_fuzz` (случайные входы с фиксированным seed), `test_cli_process` (запуск собранного бинарника)
и `contracts_lint` (`tools/check_contracts.py`: контракты функций и метки `covers:`).

## Примеры запуска

Вывод ниже получен реальным запуском бинарника.

```
$ printf 'Привет, **мир**!' | build/msgfmt
{"text":"Привет, мир!","ranges":[{"style":"bold","offset":8,"length":3,"url":""}]}

$ printf '🚀 **ок** [док](https://x.y/z) `a*b`' | build/msgfmt
{"text":"🚀 ок док a*b","ranges":[{"style":"bold","offset":3,"length":2,"url":""},{"style":"link","offset":6,"length":3,"url":"https://x.y/z"},{"style":"code","offset":10,"length":3,"url":""}]}

$ printf '2 * 3 _x_ [a](b) \\' | build/msgfmt escape
2 \* 3 \_x\_ \[a\]\(b\) \\

$ printf '\xff' | build/msgfmt; echo " code=$?"
{"error": "invalid_utf8"} code=2
```

Вывод не содержит завершающего перевода строки (здесь `echo` добавлен ради читаемости).

## Формат JSON

Компактный (без пробелов), порядок полей фиксирован.

Успех:

```
{"text":"<чистый текст>","ranges":[{"style":"bold|italic|code|link","offset":N,"length":N,"url":"<строка>"}, ...]}
```

- `offset` и `length` — в кодовых единицах UTF-16 чистого текста (🚀 = 2 единицы); `length > 0`;
- `url` присутствует у каждого диапазона; он непуст только у `link`, у остальных стилей — `""`;
- диапазоны упорядочены по `offset` по возрастанию, при равенстве — по `length` по убыванию,
  при полном совпадении — внешний (открытый раньше) стиль первым (правило 12);
- строки экранируются: `"`, `\`, `\b \f \n \r \t`, остальные U+0000–U+001F как `\u00xx` (hex в нижнем регистре);
  всё остальное, включая не-ASCII, `/` и U+2028/2029, выводится как есть.

Ошибка: `{"error": "invalid_utf8"}`.

## Коды возврата

| Код | Значение |
|-----|----------|
| 0 | успех |
| 2 | вход не является корректным UTF-8 (в обоих режимах) |
| 64 | неверные аргументы: usage в stderr, stdout пуст, stdin не читается |
| 70 | внутренняя ошибка (исключение, сбой ввода-вывода) |

## Архитектура

Заголовки — `include/msgfmt/`, реализация — `src/`. Зависимости идут сверху вниз.

| Модуль | Назначение |
|--------|------------|
| `utf8` | строгий декодер UTF-8 (`decode_utf8`), кодировщик, длина в единицах UTF-16 |
| `charclass` | `is_whitespace`, `is_letter_or_digit` — табличная классификация без `<locale>`/ICU |
| `parser` | `parse(u32string_view)`, `parse_utf8(string_view)`; рекурсивный разбор срезов; внутренние функции — в `msgfmt::detail` (`parser_internal.hpp`) |
| `escape` | `is_service_char`, `escape_text`, `escape_utf8`: результат, который `parse` вернёт как исходный текст |
| `json` | `json_escape`, `to_json`, `error_json` |
| `cli` | `run(args, in, out, err)` — тестируемая логика командной строки; `src/main.cpp` — тонкая обёртка |
| `contract` | `ContractViolation` и `MSGFMT_EXPECTS` (проверка предусловий внутренних функций, в том числе в Release) |

Сборка: статическая библиотека `msgfmt_core` (все `src/*.cpp`, кроме `main.cpp`), исполняемый файл `msgfmt`
и по одному исполняемому файлу на тестовый модуль.

## Контракты и метки covers

Каждая функция (публичная, внутренняя, вспомогательная в тестах) имеет перед собой Doxygen-контракт:
`@brief`, `@param` для каждого параметра, `@return`, `@pre`, `@post`, `@throws`. Для функций с объявлением в
заголовке полный контракт лежит у объявления, определение в `.cpp` помечено `// NOLINT(contract)`.
Нарушение предусловия внутренней функции даёт `ContractViolation`.

Каждый тест помечен комментарием `// covers: имя_функции` (через запятую можно указать несколько).
Проверка: `python tools/check_contracts.py msgfmt --tests msgfmt/tests --check-covers` (код 0 — все функции
имеют контракт и хотя бы один тест); она же запускается как тест `contracts_lint`.

## Фаззинг и свойства

`tests/test_fuzz.cpp`: свой генератор на `std::mt19937_64` с фиксированным seed (печатается при каждом
провале вместе с номером итерации и входом). Источники входов — случайные строки длиной 0–40 из алфавита
`* _ ` [ ] ( ) \ a б 1 пробел 🚀 \n` (20 000 итераций), мутации примеров Приложения А (20 000), случайные байты
и корректный UTF-8 с одним испорченным байтом (по 20 000). Инварианты для каждого входа: `parse` не бросает;
диапазоны внутри текста, отсортированы, без частичных пересечений, не режут суррогатные пары, `url` только у
`link`; `to_json` — строго корректный JSON; `parse(escape(s)) == (s, [])`; длина чистого текста в кодовых
точках не больше длины входа; `decode_utf8` и `parse_utf8` согласованы, `encode(decode(bytes)) == bytes`.

Покрытие строк (gcov, Debug, g++ 14): `utf8`, `charclass`, `cli` — 100 %; `escape`, `json`, `parser` — все
строки, кроме закрывающих скобок функций на путях исключений и `return ""` в `style_name` после `switch`
по всем значениям `Style` (недостижимо без значения enum вне диапазона, что неопределённое поведение).
Непокрытые ветви — это только пути `std::bad_alloc`.

## Принятые решения

Полная таблица с тестами — `docs/decisions.md`. Главное:

- **Пример 9.** В ТЗ вход записан двумя способами; правила приоритетнее. `**жирный _и курсив_**` даёт
  bold(0,15) + italic(7,8), `**жирный _и_ курсив**` — bold(0,15) + italic(7,1). Тестируются оба.
- **Поиск закрывающего маркера.** Ищется в сыром тексте внутри границ внешнего среза; экранированный символ
  маркером не считается; code-span при поиске внешнего закрывающего не учитывается; перед закрывающим маркером
  обязан стоять непробельный символ. Содержимое пары разбирается рекурсивно только внутри пары, поэтому
  частичных пересечений нет. Внутри `` ` `` экранирования нет.
- **Пустое содержимое.** `****`, ``` `` ```, `__` — не конструкции, символы выводятся как обычные;
  диапазонов нулевой длины не бывает.
- **Вложенные ссылки.** Стили внутри текста ссылки разрешены; `[` внутри текста ссылки — литерал; текст
  заканчивается на первом неэкранированном `]`, `\]` даёт `]`; `(` идёт сразу за `]`; url берётся как есть
  (экранирование не действует), непустой, без пробельных символов и `)`.
- **Буквы/цифры и пробелы.** Открывающий `_` требует перед собой начало текста или не букву/цифру, а после
  себя — непробельный символ; закрывающий `_` — после себя конец текста или не букву/цифру (правило 3). «Пробельный» —
  ровно символы со свойством Unicode White_Space (список в контракте `is_whitespace`; U+200B и U+FEFF не
  пробелы). «Буква или цифра» — таблица интервалов категорий L* и Nd без `<locale>`.
- **Вывод без завершающего перевода строки.** Ни JSON, ни результат `escape` не получают добавочного `\n`.
- **Неверные аргументы.** Код 64 (EX_USAGE), usage в stderr; любые аргументы, кроме отсутствия или единственного
  `escape` (включая `--help`), — ошибка. Внутренняя ошибка — 70.
- **UTF-8.** Декодер строгий (overlong, суррогаты, > U+10FFFF, оборванные последовательности — ошибка);
  NUL, BOM и управляющие символы допустимы. Ввод-вывод бинарный (на Windows `_setmode`).
- **Тотальность `parse`.** Недопустимые скалярные значения в `u32string` заменяются на U+FFFD.

## Известные ограничения

- Таблицы Unicode написаны вручную, без ICU: `is_letter_or_digit` приближает категории L* и Nd.
  Комбинирующие знаки (Mn/Mc), в том числе гласные знаки индийских письменностей и тайские гласные,
  и некоторые письменности (эфиопская, кхмерская, лаосская, тибетская, мьянманская и др.) не считаются
  буквами; перечень — в контракте функции. Версия Unicode зафиксирована в таблицах.
- Нормализации (NFC/NFD) нет: `é` одной кодовой точкой и `e` + U+0301 — разные тексты; позиции считаются
  по кодовым точкам и единицам UTF-16, а не по графемам.
- Худший случай по времени — O(n²) на длинных цепочках незакрытых маркеров; глубина рекурсии не больше 4.
- Весь вход читается в память целиком.
